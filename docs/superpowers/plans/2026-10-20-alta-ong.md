# Alta de ONG (`/alta-ong`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hidden SPA route `/alta-ong` that registers an ONG with its service categories (rubros) in Bonita, the National API and the app DB in one operation.

**Architecture:** New backend service `app/services/alta_ong.py` orchestrates three steps with compensation (delete the Bonita user if a later step fails). `BonitaClient` and `NacionalClient` gain the few calls needed. A public router endpoint `POST /api/ongs/alta` (plus a public catalog `GET /api/ongs/alta/tipos-recurso`, because `/api/tipos-recurso` requires a session) feeds a new React page with no menu link.

**Tech Stack:** FastAPI, SQLAlchemy, pydantic v2, requests, pytest + `responses`; React + TypeScript (Vite).

**Spec:** `docs/superpowers/specs/2026-10-20-alta-ong-design.md`

## Global Constraints

- Branch `feat/alta-ong`, PR to `dev`. Commits in English, conventional format, no emojis, no AI attribution lines.
- Strict TDD on the backend: failing test first, then code.
- UI copy and error `detail` in Spanish (neutral, like the existing app). Code identifiers follow existing Spanish naming.
- No DB migration, no changes in `nacional/` or in any `.bos`.
- Bonita user password = `settings.bonita_test_password`; Bonita membership = group `/rescuesync/ong`, role `representante_ong`.
- App + National API password = the one the user typed (min 8, max 128). Username 3-60. ONG name and contact name 2-120.
- CUIT stored and sent as `NN-NNNNNNNN-N` (input accepted with or without dashes, pattern `^\d{2}-?\d{8}-?\d$`).
- Rubros: at least one, no repeated `tipo_recurso`, `cantidad_total` integer ≥ 0 (0 is valid).
- Route `/alta-ong` must not be linked from any menu, the login page or `Shell`.
- Run backend tests from `backend/` with `.venv/Scripts/python.exe -m pytest -q`; full check `python scripts/verificar_todo.py` from repo root; front `npm run build` in `frontend/`.

## Review Focus

1. CUIT typed without dashes (`30712345678`) must be detected as duplicate of the seeded `30-71234567-8`-style value and stored normalized — Task 3 test `test_cuit_sin_guiones_se_normaliza_y_detecta_duplicado`.
2. Username / names with surrounding spaces (`"  ong.caritas "`) must be trimmed before every system call — Task 4 test `test_alta_recorta_espacios`.
3. National API timeout or outage (not a 409) after the Bonita user exists must delete that Bonita user and return 503 — Task 3 test `test_nacional_caido_borra_usuario_bonita`.
4. Bonita reachable but login fails (wrong technical password, no `X-Bonita-API-Token` cookie) must return 503 and create nothing — Task 3 test `test_bonita_login_falla_no_crea_nada`.
5. Double submit (same form posted twice) must yield 409 the second time without touching Bonita or the National API — covered by Task 3 test `test_duplicado_local_no_llama_a_nadie`.

### Task 3: `alta_ong` service with compensation

**Files:**
- Create: `backend/app/services/alta_ong.py`
- Test: `backend/tests/test_alta_ong.py` (new)

**Interfaces:**
- Consumes: Task 1 (`registrar_ong`, `declarar_inventario`, `NacionalError.status`, `FakeNacional`), Task 2 (Bonita methods), `hash_password` (`app/core/security.py`), `Ong`, `Usuario`, `Rol.ONG`.
- Produces:
  - Constants `BONITA_GRUPO_ONG = "/rescuesync/ong"`, `BONITA_ROL_ONG = "representante_ong"`.
  - `class AltaOngError(Exception)` with `(mensaje: str, status: int = 409)` and `.status` (same shape as `CicloError`).
  - `normalizar_cuit(cuit: str) -> str` — digits only → `NN-NNNNNNNN-N`; `AltaOngError(..., 422)` if not 11 digits.
  - `@dataclass DatosAlta(ong_nombre: str, cuit: str, nombre: str, username: str, password: str, rubros: list[dict])` (rubro dict = `{"tipo_recurso": str, "cantidad_total": int}`).
  - `alta_ong(db: Session, settings: Settings, nacional: NacionalClient, datos: DatosAlta) -> Usuario` — the created ONG user (with `.ong` loaded).

Order and error mapping (from the spec, "Orden de la operación"):
1. Local duplicate (username, ONG name or normalized CUIT) → `AltaOngError("... ya está registrado", 409)`; nothing else is called.
2. Bonita: `BonitaClient(settings.bonita_base_url, settings.bonita_timeout_seconds)`, `login(settings.bonita_username, settings.bonita_password)`; `find_user_id` not None → 409; create user with `settings.bonita_test_password`, `group_id(BONITA_GRUPO_ONG)`, `role_id(BONITA_ROL_ONG)`, `add_membership`. Any `BonitaError`/`requests.RequestException` here → 503 `"Bonita no responde; probá de nuevo en un momento."` (if the user was already created, delete it first).
3. `registrar_ong` fails → delete Bonita user; `status == 409` → 409 with the API's detail; otherwise 503 with `NACIONAL_CAIDO` text (`"El Sistema Nacional no responde; probá de nuevo en un momento."`).
4. `declarar_inventario` fails → delete Bonita user, no local rows; 502 with detail: `"La ONG quedó registrada en el Sistema Nacional pero sin rubros: completalos desde Swagger con PUT /ongs/{cuit}/inventario."` (with the real CUIT).
5. Create `Ong(nombre, cuit)` + `Usuario(username, password_hash=hash_password(password), nombre, rol=Rol.ONG, ong=...)`, commit. `IntegrityError` → rollback, delete Bonita user, 409 `"La ONG quedó registrada en el Sistema Nacional pero ya existe en la app."`.
6. Failures while deleting the Bonita user during compensation are swallowed (the original error is the one reported).
